# 踩过的坑

下面每一条都发生在用这个工具包做一支完整歌词 MV 的过程中，大多数浪费过一次渲染或一轮返工。

## 1. 节拍和歌曲

- **你听不见，所以先测，再问。** `analyze_audio.mjs` 测速度很准（实测误差 0.01 BPM）。但它对"第一个强拍在哪"的投票只是参考：
  在测试歌曲上，它投的和片子里看起来对的那个并不一样。选定一个，让所有律动和切镜都跟它走，然后请对方看角色是不是踩在拍子上。
- **`.lrc` 只标了每句的开头。** 更细的都是你放的：括号里的和声、一拍一个词的句子（"海边 / 点起 / 烟火"）、
  句尾拖长的那个词、一口气报出来的清单。把它们放在拍子网格上，用 `--envelope` 找乐句之间的空隙，并把每一个都列出来请对方核对。
- **每句的结尾也是你定的。** 让字幕在下一句开始之前消失；一句话赖在新画面下面，看起来像出错了。
- **歌词的空档是给画面的时间。** 没有歌词的小节正好放一个不用和歌词抢注意力的画面梗。要提前设计，别让它空着。

## 2. 故事和连贯性

- **记住东西在哪。** 一个镜头里放下的道具就留在那里。在分镜里维护"东西在哪"那张表，写每个新镜头之前对照一遍。
- **画面会被看错，而看错的版本可能更好。** 地上的一道长影子被看成了火箭降落，最后火箭取代了影子。
  早点给静帧，让"看错"的代价很低。
- **不要在主角的脸上或身上留下永久的东西。** 额头上的印章、手臂上的行李牌先后都被否了：简单的角色身上多一个标记，
  之后每个镜头都会显得"丑"。如果故事需要主角带着某样东西，找一个不破坏轮廓的办法（他把车票吞进了肚子，需要时再拿出来）。
- **第二遍副歌，歌词相同。** 对着第一遍来设计：同一条路、同样的障碍，不一样的角色状态。
- **首尾呼应要"同样的处理"，不是"类似的处理"。** 叠在热闹画面上的大字，和白底上孤零零的大字并不呼应。
  两个时刻要互相回答时，背景、脸、字体、位置都对齐，只改一样东西。
- **同一句话不要出现两遍。** 某个词单独放大时，那几秒的字幕里就不要再有它。

## 3. 角色

- **用这套班底的画法来画。** 带眉毛、睫毛、写实比例的客串角色看起来像从别的片子里来的。
  平涂、一条墨线轮廓、班底通用的眼睛和嘴、头占身体的大半。
- **在一张图上定大小。** 客串角色和路人都是整片渲染之后才被要求放大的。在任何场景使用之前，把所有人按实际大小并排放在一张图上。
- **`emotions()` 换表情时会从 Clawd 的颜色过渡。** 其他角色要在每个关键点里带上自己的颜色
  （见 `src/guests.js` 里的 `whale.emotions`），否则每次换情绪都会闪半秒橙色。
- **手臂。** Clawd 的手臂平时是向两边伸直的；手臂自然下垂的角色需要把工具包的手臂数值重新映射，否则每个表情都像稻草人。
- **被挡住的身体。** 站在柜台后面的角色，眼睛必须高于柜台：把眼睛的位置算出来，不要目测。
- **标志性的特点不是错误。** 如果一个角色以某种怪癖出名（有个客串角色总在流口水），就默认带着它。

## 4. 文字和字体

- **工具包的默认字体没有中文。** 把需要的字体作为本地文件打包，在 `studio.html` 里声明。
  永远不要从网络加载字体：一次字体服务器响应慢，就让渲染卡死了。
- **让对方看图选字体**，图上是片子自己的字（`font_sheet.mjs`）。他们会选一个你想不到的。
- **字体只有一种粗细？假加粗要小心。** `write(..., { bold })` 会把笔画加厚。笔画密的字很快就糊：
  270 像素、两个简单的字可以用 .06；"不算虚拟"最多只能到 .035。渲染一张不同粗细的对比卡，让对方选。
- **文字不受 `push()` / `translate()` 影响。** `write()` 和 `letter()` 只通过镜头定位。
  要让文字跟着一块会滑动或抖动的面板走，把位移加到文字自己的坐标上。
- **文字是最后合成的。** 如果角色或转场要从招牌前面经过，在写完招牌上的字之后调用 `flushLetters()`。
- **对方自己写的字比字体好。** 用 `cutout.mjs` 抠出来，用 `sticker()` 放。深色手写字放在深色画面上需要提亮（`--relight`）。
- **标题不要和布景叠在一起。** 标题在画面上时让镜头停在空旷的天空，之后再移到布景。

## 5. 引擎和场景代码

- **变量不要叫 `pop`、`push`、`scale`、`rotate`、`color`、`fill`……** p5 把这些放在全局对象上；
  局部写一个 `const pop = …`，下一次调用 `pop()` 就会报 "pop is not a function"。
- **`image.decode()` 在后台标签页里永远不返回**，而渲染器的各个工作页面就是标签页。要等 `load` 事件
  （见 `cutout.mjs` 生成的文件）。症状是：某个工作页面 60 秒后超时，其他页面还在渲染。
- **光。** 用 `glow()`；黄色画在蓝色上会变绿。给蓝色角色加"金色"色调同样会变绿：改成往暖白色偏。
- **水彩填充贵，平涂几乎不要钱。** 水彩 `fill` 是最耗时的笔触。大块平面用 `wash`。
- **比画布大很多的形状**可能丢失轮廓线：传 `ink: null`，自己画边。
- **一个场景一个函数。** 一个地方只画一次，在那里的每个镜头里调用；镜头和角色放在镜头函数里。
  如果第二个场景文件也要用，就把共用的布景导出。
- **不要在每个镜头里手动给角色挂状态。** 如果主角从第 4 个镜头起一直戴着什么，把调用包一层
  （`const lead = (x, y, u, o) => clawd(x, y, u, { ...o, hat: 'beanie' })`），之后都用这个包装。

## 6. 渲染

- **在一个浏览器里加进程没用。** 标签页共用一个显卡进程：3 个进程和 6 个进程都是约 620 毫秒一帧。
  独立的浏览器才能叠加：在一台 6 核 CPU、中端显卡的电脑上，8 个浏览器达到约 230 毫秒一帧。`render_all.mjs` 就是这么做的。
- **渲染可以断点续渲，中断不会损失任何东西。** 每一帧只由时间决定，并且是整帧写入的。
- **合成之前核对帧数。** 一次被打断的渲染曾经产出过一支只有六秒的"完整成片"。`render_all.mjs` 在帧不齐时拒绝合成。
- **残留的旧帧。** 如果片子变短了，清空 `out/frames`；合成时会读取里面的每一个文件。
- **按镜头重渲，不要靠猜。** `rerender.mjs` 逐字节比较。它对抽样到的帧（每半秒一帧）是精确的，对两次抽样之间的变化是盲的：
  短暂的改动要加 `--range`。
- **发到网上的演示文件不是母版。** 母版很大（大约每秒 1.4 MB）。另外压一份小的用来分享；母版保留。

## 7. 和用户协作

- **先问。** 开工前的几个问题，比任何优化省下的时间都多。
- **用图片给选项**：字体、粗细、一个角色的三种大小。用文字描述的选项，得到的回答往往是"我不确定"。
- **说清楚你没验证过什么。** "我没有听过声音""我检查的是静帧，不是动作"应该出现在每一次汇报里。
- **好点子是他们的。** 内部梗、他们想放进去的人物、他们亲手画的片名：给这些留位置。
- **版权由他们判断，但你要说一次。** 一首歌、一个乐队的角色、别家公司的吉祥物：注明出处不等于获得许可。
  不要说教，也不要假装这个问题不存在。
- **没有得到"可以"，绝不渲染整片**（除非他们关掉了这个确认点）。

## 8. 电脑环境（Windows）

- 可能没装 Chrome；Edge 一定有，而且能用。工具包两个都会找。
- PowerShell 5.1：没有 `&&`；.NET 的文件操作不认 shell 的当前目录，要给绝对路径。
- 东西装在哪，跟着用户的习惯走（有位用户所有东西都装在 `D:` 盘）。
- 可能没有 `git`。安装任何东西之前先问。
