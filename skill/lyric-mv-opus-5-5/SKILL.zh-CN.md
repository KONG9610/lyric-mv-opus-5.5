# 歌词 MV（手绘风，面向 Claude Opus 5.5）

> 这是 `SKILL.md` 的中文版，内容一一对应。Claude 实际加载的是 `SKILL.md`；这份给人读，也给用中文工作的 Claude 对照。

你要用"慢但是好"的方式做一支 MV：先读懂歌，和对方把故事谈定，用代码把它画出来，自己看自己渲染的画面，对方说"可以"
之后才渲染整片。画面用 p5.js 和 p5.brush 绘制：平涂、会抖动的墨线、纸张纹理。除非对方另有要求，主角是 Clawd。

和对方交流、写分镜和交接文档，都用对方使用的语言。

## 动手之前：找到工具包，并说清楚你做不到什么

**工具包**就是这个 skill 所在的仓库（里面有 `render.mjs`、`ANIMATION_GUIDE.md`、`scripts/`）。按这个顺序找：环境变量
`LYRIC_MV_KIT`；本文件旁边 `kit-path.txt` 里写的路径；工作目录附近名为 `lyric-mv-opus-5.5` 的文件夹。都没有就问对方它在哪，
或者提出帮忙克隆。它需要 Node.js、Chrome 或 Edge、ffmpeg；第一次要在里面运行一次 `npm install`。

**画任何东西之前，完整读一遍工具包里的 `ANIMATION_GUIDE.md`。** 那是手艺：媒介、给"只看一遍的观众"的节奏、动画原理、
引擎和 Clawd 的接口。本 skill 只补充"一首歌"额外需要的东西，不重复它。然后读这里的 `references/pitfalls.zh-CN.md`：
里面每一条都在真实项目里浪费过一次渲染或一轮返工。

**尽早告诉对方三件事**，因为每一件都会改变他们需要给你什么、核对什么：

- 你听不到歌。速度和拍点是脚本测出来的；一句歌词里某个字落在哪是估计的。之后会请他们用耳朵核对一小张时间表。
- 你不能生成图片。所有角色都是照着描述或参考图用代码画的，所以会像参考图，但不会一模一样；使用之前他们会先看到设定图。
- 工具包自己的规则是"画面上不出现文字"。歌词 MV 是有意打破这条的：歌词就是文字。说一次，让他们来决定。

## 确认到什么程度

开工时问一次，把答案写进项目的 `BRIEF.md`。默认四个确认点全开：

1. 分镜通过，才写场景代码；
2. 每个新角色的设定图通过，才放进场景；
3. 静帧（或几秒片段）通过，才渲染整片；
4. 修改之后的静帧通过，才做局部重渲。

如果对方说"你自己看着办"，就一路做到底，只展示成片和那张"估出来的时间点"清单。介于两者之间也可以：把开了哪几个写清楚。

为什么要有确认点：一首三分钟的歌渲染整片要一刻钟以上，而人看到东西之后会改主意——故事、角色、字体都会改。
一张静帧只要一秒。永远不要为了"看看效果"去启动整片渲染。

## 工作顺序

### 1. 收料

需要：音频文件，和带时间的歌词（`.lrc`；只有纯文本歌词也能做，但那样每句的开头也成了估计值）。问清做哪一段
（一分钟还是整首：整首大约是三倍工作量）、画幅（工具包画的是 16:9，1920×1080）、做来干什么。

```bash
node scripts/new_project.mjs <名字> --audio=<歌曲> --lrc=<歌词>   # 在工具包根目录运行；有适用的角色包就加 --cast=<包名>
cd projects/<名字>
node ../../scripts/analyze_audio.mjs assets/song.mp3 --lrc=assets/lyrics.lrc
```

每支片子在 `projects/` 下有自己的文件夹，里面有自己的 `studio.html`、`config.js`、`scenes/`、`assets/`、`out/`。
所有命令都在这个文件夹里运行。`analyze_audio` 会打印速度和第一个强拍的四个候选；选那个能让歌词句子落在小节线上
（或小节线前一点）的，把 `bpm` 和 `offset` 写进 `config.js`，并把这个选择列进请对方核对的清单。

**角色包。** 工具包里的 `casts/<包名>/` 放的是不属于公开部分的角色（某个乐队自己的形象、客户的吉祥物）。如果 `casts/`
里某个包的 `CAST.md` 写明它属于这位歌手或这位用户，就加载它（`--cast=<包名>`），并告诉对方你加载了。
永远不要把角色包里的角色复制到工具包的公开部分。

### 2. 读歌词，然后说出你认为这首歌在讲什么

先全部读完，再提任何方案。用几句话告诉对方：谁在对谁说话，从第一句到最后一句发生了什么变化，哪几句分量最重。
然后给一句话的故事。

留意那些可以变成**画面里的东西**、而不只是画面上的字的歌词：把一句词演出来，比把同一句词写两遍有力；
歌词和画面之间的双关是观众会记住的东西。问对方有没有想放进去的梗、典故或人物——第一支片子里最好的点子都来自用户，不是模型。

### 3. 角色

默认主角：Clawd。问还有谁出场、彼此是什么关系；关系由故事决定。

- 自带的客串角色：`src/guests.js` 里的 `whale()`（鲸鱼）、`doubao()`（豆包）和 `wisp()`（小圆球路人）。
  前两个是对其他 AI 产品形象的善意同人画法：故事和 AI 有关、且对方想用时再用，并注明出处。
- 新角色需要参考图或清楚的描述。用这套班底的画法在代码里画（平涂、墨线、同一套眼睛和嘴的画法），让它读取和 `clawd()`
  相同的参数，这样 `feel()`、`emotions()`、`turn()` 都能驱动它；然后渲染设定图：它的各个视角、一排表情，
  以及**全员按实际使用大小站在一起**的比例图。简单角色照 `src/guests.js` 写；有五个视角的完整角色照角色包里的代码写。
- 真实品牌的吉祥物、真人的形象，用不用由对方决定并负责；把这一点明确说一次。

### 4. 分镜（确认点 1）

填写项目里的 `STORYBOARD.md`（模板已经在里面）。它比指南里的格式多出这些，原因如下：

- **埋设与回收**对照表。长片靠"回到之前出现过的东西"连成一体。
- **东西在哪**：每个会持续存在的道具和角色，逐镜头记录位置。写每个新镜头前对照一遍。
  （第一支片子里，行李箱在第 1 个镜头留在了柜台，第 9 个镜头却想让主角在海边"打开它"。）
- **画面上的字**：哪些句子是字幕，哪几个词单独放大，哪些变成画面。
- **估出来的时间点**：所有不是直接来自 `.lrc` 的时间。
- 重复的副歌歌词一样：第二遍要对着第一遍来设计（同一个地方，不同的结果），不要把同样的画面再放一遍。
- 在小节线上切镜头。一小节是 `240 / bpm` 秒。

用几行话讲故事，把待定事项列成简短的编号清单。改到对方通过为止。

### 5. 角色设定图和字体（确认点 2）

- 设定图：见第 3 步。跳过"全员同框"那张，大小就会在后期返工。
- 字体：`node ../../scripts/font_sheet.mjs --text="<片中的大字>" --latin="<外文短语>"` 会把所有自带字体套在片子自己的字上，
  出一张对比图。让对方选。字幕用一种字体；少数几个大字用另一种，让片子有两种"声音"；有外文短语的话再用第三种。
  对方自己的字体放进项目的 `assets/fonts/`，并在项目的 `studio.html` 里声明。字体永远用本地文件。
- 如果对方给了自己写的字（比如亲手画的片名），用 `scripts/cutout.mjs` 抠出来，用 `sticker()` 放进画面。这通常比任何字体都好。

### 6. 制作，并且看

一个镜头一个镜头地写 `scenes/*.js`，按指南里的检查流程走。最要紧的几点：

- 每个背景画成一个函数、反复调用；每个角色给一个 `boilKey`；歌词放在一张 `LINES` 表里，每个镜头之后用 `subtitles()` 画出来。
- 用抽帧总览图（`node ../../render.mjs --sheet=…`）、连续帧条（看动作）、局部放大（看表情）检查自己的成果。光读代码看不出动作。
- Clawd 以外的角色需要各自的 `emotions` 包装（`whale.emotions`、角色包里的 `x.emotions`）：工具包原来的 `emotions()`
  在换表情时会从 Clawd 的颜色过渡。

### 7. 静帧，然后渲染（确认点 3）

给对方看关键时刻的静帧总览图；凡是"节奏才是重点"的地方，再给几秒片段
（`node ../../render.mjs --clip --range=27.6:31.6 --out=out/check/x.mp4`）。列出改了什么、你已经知道哪里还弱。等一个明确的"可以"。

```bash
node ../../scripts/render_all.mjs --out=out/<名字>_v1.mp4
```

它会按这台电脑自动调整：同时启动多个**独立的浏览器**（而不是在一个浏览器里加进程——那样它们会排队用同一个显卡进程），
每个渲染自己的一段；可以断点续渲；只有每一帧都齐了才合成；它会打印并记住达到的速度。
如果对方说显卡或 CPU 很闲，就调大 `--browsers`；电脑吃力就调小。

跑完之后：核对它打印的帧数和时长，从成片里抽几帧出来看，然后才发给对方，并附上"估出来的时间点"清单。

### 8. 修改（确认点 4）

小改动很便宜，要告诉对方：不应该有人因为怕麻烦而不敢提修改。

```bash
node ../../scripts/rerender.mjs --dry                 # 哪些镜头变了？（不动任何文件）
node ../../scripts/rerender.mjs --out=out/<名字>_v2.mp4
```

它会把每个镜头抽样重渲，和硬盘上已有的帧逐字节比较，只重渲不一样的镜头，然后合成。
如果改动短于半秒、又在一个很长的镜头中间，另外加上 `--range=a:b`。改的是共用的东西（某个角色的画法、字幕样式）时，
所有用到它的镜头都会变；开始之前告诉对方这次要重渲多少。

除非这个确认点关了，否则先给对方看改动的静帧。片子的每个版本都保留（`_v1`、`_v2`……）；不要覆盖他们上一次认可的那版。

### 9. 收尾

更新 `BRIEF.md`：做过的决定、各个版本、还没核对的东西、这次出过什么不该再出的问题。
如果之后由新的会话接手，交接文档和分镜就是它能拿到的全部。

## 怎么汇报

说实话：你渲染了什么、看过什么，哪些只是估的，你知道哪里弱，花了多久。
"渲染完成，4745 帧，我看了其中 6 帧；我没有听过声音"是一份好汇报。帧数和时长与歌曲对上之前，不要说渲染完成了。
